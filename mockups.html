IdleViz UI mockups

The two native UIs, and how to build them. project.md points here: build the menu-bar popup and the settings window to match these mockups. Only layout, grouping, row order and sizing are fixed. Colors, fonts and exact spacing come from the system controls.

These are HTML previews, not code to port. Both UIs are native Swift (AppKit plus SwiftUI). The HTML only shows what goes where.

1. Menu-bar popup

Opens from the menu-bar icon. It is a small popover with a liquid-glass look, like the system Battery menu, instead of a plain NSMenu.

Wi-FiBatteryIdleVizTue 9:41
Settings…⌘,
Open visualizer⌃⌥V

Contents

  • Exactly two rows. No Quit item here or in settings.
  • Settings… is the only clickable row. It opens the settings window.
  • Open visualizer is informational and dimmed. It shows the current hotkey, read from KeyboardShortcuts so it updates when the shortcut changes.

Build notes

  • Use a popover, not NSMenu: SwiftUI MenuBarExtra with the .window style, or an NSPopover with a material background. NSMenu cannot be given this look.
  • Glass look: translucent fill, strong blur, thin light edge, about 22 pt corner radius, soft shadow. Rows have a rounded highlight on hover.
  • Width about 260 pt. Height is just the two rows.
  • The menu-bar icon still flashes (alt icon 2 to 3 times over about 1 s) when a manual open is refused.

Window

  • A normal NSWindow with SwiftUI content. Fixed width of about 340 pt and a fixed height of about 560 pt. The content scrolls inside (ScrollView).
  • Not resizable and cannot go fullscreen: leave .resizable out of the style mask, set collectionBehavior = [.fullScreenNone], and disable the zoom (green) button. That also stops the ⌃⌘F shortcut.
  • Keep close (the red button) and minimize. There is no Quit row: the red button closes the window and ⌘Q quits the app.
  • The app switches to .regular activation policy while the window is open so it can take focus, then back to accessory on close. ⌘Q works while it is focused.

Sections, in this order

Section Rows
General Idle timeout (5, 10, 15, 30 min, Off), hotkey recorder (KeyboardShortcuts.Recorder), Open now, Launch at login
Visualizer Show Spotify overlay, Brightness (50 to 100%), Mode (Single or Shuffle), then the rows for that mode (see below), Favorites, Blocklist
Presets Plugin trust warning, Import…, Open folder, Reload, list of presets and plugins that failed to load (each with its error and a Reveal button)

Build notes

  • Use native controls (Picker, Toggle, Slider, Button). Rows are a label on the left and one control on the right, grouped into rounded cards under a section heading.
  • Keep it compact: small text, tight rows, and a short hint under a label only when the label alone is unclear.
  • Settings are stored in UserDefaults. Controls write them and the helper applies changes live (for example, brightness updates the open window immediately).
  • Mode is Single or Shuffle. The mockup shows Shuffle, which has three rows: Shuffle from (All, Bundled, Custom, Favorites), Seconds per preset and Blend time. In Single, those three rows are replaced by one row, Visualizer, a picker listing every preset and plugin (bundled and custom), and the current preset stays on screen until changed.
  • Show Spotify overlay off means the page shows only the visualizer and dim layer: no now-playing layout in any state, not even the paused progress bar. Brightness, mode and the rest behave the same.
  • Favorites and Blocklist open a sheet listing presets.
  • The failed-to-load section is hidden when nothing has failed.
  • Dark mode: there is no setting. The window follows the macOS appearance, and native SwiftUI controls and system colors (.primary, .secondary, Color(nsColor:) semantic colors, the accent color) switch on their own. Don't hard-code light colors. The Light, Dark and System buttons above only preview this in the browser.
Still to decide (ask before building):
  • How the glass effect works on macOS older than 26, since the app targets 14.2 and later. Use a plain blur material as a fallback, or raise the minimum version?
  • Whether Favorites and Blocklist stay as Manage sheets, or become an inline searchable list.
