IdleViz UI mockups

The two native UIs, and how to build them. project.md points here: build the menu-bar popup and the settings window to match these mockups. Only layout, grouping, row order and sizing are fixed. Colors, fonts and exact spacing come from the system controls.

These are HTML previews, not code to port. Both UIs are native Swift (AppKit plus SwiftUI). The HTML only shows what goes where.

1. Menu-bar popup

Opens from the menu-bar icon. It is a small popover with a liquid-glass look, like the system Battery menu, instead of a plain NSMenu.

Open visualizer⌃⌥V
⚠︎
Spotify control not allowedOpen System Settings ›

Contents

  • Two rows, plus one error row per missing permission. No Quit item here or in settings.
  • Settings… opens the settings window.
  • Open visualizer is informational and dimmed. It shows the current hotkey, read from KeyboardShortcuts so it updates when the shortcut changes.
  • Error rows (shown here) appear below Open visualizer only while a required permission is missing: "Spotify control not allowed" (Automation) or "Spotify audio blocked" (System Audio Recording). Clicking one opens the matching System Settings privacy page. While any error row is showing, the menu-bar icon is tinted yellow.

Build notes

  • Use a popover, not NSMenu: SwiftUI MenuBarExtra with the .window style, or an NSPopover with a material background. NSMenu cannot be given this look.
  • Glass look: translucent fill, strong blur, thin light edge, about 22 pt corner radius, soft shadow. Rows have a rounded highlight on hover.
  • The app requires macOS 26, so the background is always the real Liquid Glass (glassEffect). No fallback for older versions.
  • Width about 260 pt. Height fits the rows.
  • The menu-bar icon still flashes (alt icon 2 to 3 times over about 1 s) when a manual open is refused.
  • Yellow icon: swap the template image for a non-template copy tinted NSColor.systemYellow, and switch back once every permission is fixed. Re-check permissions each time the popup opens.

Window

  • A normal NSWindow with SwiftUI content. Fixed width of about 340 pt; it opens about 640 pt tall and the height can be dragged. The content scrolls inside.
  • Cannot go fullscreen: set collectionBehavior = [.fullScreenNone] and disable the zoom (green) button. That also stops the ⌃⌘F shortcut.
  • Keep close (the red button) and minimize. There is no Quit row: the red button closes the window and ⌘Q quits the app.
  • The app switches to .regular activation policy while the window is open so it can take focus, then back to accessory on close. ⌘Q works while it is focused.

Build notes

  • Use native controls (Picker, Toggle, Slider, Button). Rows are a label on the left and one control on the right, grouped into rounded cards under a section heading.
  • A folded row is a DisclosureGroup with its rows inset under it. A row that depends on a switch is greyed out while the switch is off, not hidden, and turning the switch on opens the row. Which rows are open is not stored: Mode starts open, the others closed. Mode swaps its rows between Shuffle and Single instead of greying them out.
  • Keep it compact: small text, tight rows, and a short hint under a label only when the label alone is unclear.
  • Settings are stored in UserDefaults. Controls write them and the helper applies changes live (for example, brightness updates the open window immediately).
  • Mode is Single or Shuffle. The mockup shows Shuffle, which has three rows: Shuffle from (All, Bundled, Custom, Favorites), Time per preset and Blend time. In Single, those three rows are replaced by one row, Visualizer, a picker listing every preset and plugin (bundled and custom), and the current preset stays on screen until changed.
  • Show Spotify overlay off means the page shows only the visualizer and dim layer: no now-playing layout in any state, not even the paused progress bar. Brightness, mode and the rest behave the same.
  • Time per preset offers 15 s, 30 s, 45 s, 1 min, 2 min and 5 min. Blend time offers 0, 1, 2.7, 5 and 8 s.
  • Like key, Skip key and Block key work while the visualizer is open, where every other key closes it. Like adds the preset on screen to the favorites, or takes it off again. Skip shows the next one in Shuffle mode. Block puts the preset on the blocklist and, in Shuffle, skips on. Click a row's button, which then says "Press a key", and press one: any key but Esc and the modifiers. Esc, or a click elsewhere, keeps the old key; a key another row uses is refused ("In use, press another"); ✕ means no key ("Not set"). While Close on input is off the three rows are greyed out and say "Needs Close on input".
  • In Single mode the Visualizer row is a button with the preset's name and a magnifier. It opens a sheet with a search box and every preset as a list, scrolled to the current one; picking a row applies at once. The Favorites and Blocklist sheets have the same search box on both tabs and a Preview button (▷) on every row, which opens the visualizer held on that preset without changing the stored controls.
  • Show visualizer title puts the name of the preset on screen in the top left corner, in small type. Off by default.
  • Last shown names the preset that was last on screen, with a Favorite button and a Block button. Any input but the like and skip keys closes the visualizer, so this is how a preset you just watched gets blocked, or liked after the fact. The row is hidden until a preset has been shown.
  • Favorites and Blocklist open a sheet with two tabs: the presets on that list, where entries can be removed, and all presets with a search field, where they can be added. A preset is never on both lists.
  • The failed-to-load section is hidden when nothing has failed.
  • Different times on battery: the two "On battery" rows are hidden while the switch is off. The first time it's turned on, they start with the same values as the rows above. On a Mac with no battery (Mac mini, iMac, Mac Studio, Mac Pro), the switch and both rows are hidden entirely.
  • Audio delay is saved separately for each output device. The hint under the label names the current device, and the slider moves when you switch speakers or headphones. A device used for the first time starts at the delay macOS reports for it.
  • Detect with the microphone: press Detect while Spotify plays out loud. The button shows "Listening…" for about 5 s, then the slider jumps to the result. If it can't hear the music clearly (too quiet, or headphones), the hint says so and the value doesn't change. If microphone access is denied, the hint says so and links to System Settings.
  • Manual delay test: Start opens a sheet with a panel that lights up, the delay slider with −10 ms and +10 ms buttons, and Done. A beep plays every second and the panel lights up one audio delay later; the slider is dragged until they land together. Every fourth beep is higher and its flash is orange. Spotify is paused while the sheet is open.
  • Dark mode: there is no setting. The window follows the macOS appearance, and native SwiftUI controls and system colors (.primary, .secondary, Color(nsColor:) semantic colors, the accent color) switch on their own. Don't hard-code light colors. The Light, Dark and System buttons above only preview this in the browser.
